## 4. Disposition of ARCHITECTURE_REVIEW_PROMPT.md items 1–10

**1. S0 retains one immutable artifact per physical archive while the Source Manifest owns the ordered aggregate identity.**
SATISFIED. `SourceFileIdentity` (`rcc002/s0/source_identity.py:74-101`) is a frozen, `slots=True` dataclass representing exactly one physical archive's byte-derived facts (checksum, size, record count, coverage). `scan_binance_vision_archive()` (`:169-304`) never sorts or assigns a real ordinal — it always returns ordinal `0` as a placeholder for a single-file scan. Ordering and ordinal assignment happen exclusively in `build_source_snapshot()` (`:409-485`), which sorts by `provider_relative_name` and reassigns ordinals via `dataclasses.replace` (never in-place mutation), then validates the result in `_validate_snapshot_files()`. `SourceManifest.__post_init__` (`rcc002/s0/manifest.py:280-332`) then re-derives the canonical snapshot from its own stored `source_files` and rejects any manifest whose stored array is not exactly that canonical, ordered array (`RCC_SOURCE_FILE_ORDER_MISMATCH`, `manifest.py:332`). Ownership of the *ordered aggregate identity* is unambiguously the Manifest/Snapshot layer; per-archive immutability is unambiguously the `SourceFileIdentity` layer.

**2. Registered and historical generic ingestion paths are separated without allowing the legacy path to bypass new canonical controls.**
PARTIALLY SATISFIED — see **ARCH-01**. The two paths are cleanly separated at the type/module level (`ingest_source`/`LegacySourceManifest` vs. `scan_binance_vision_archive`/`build_source_snapshot`/`SourceManifest`), and the separation is documented at both `ingest.py:7-15` and `IMPLEMENTATION_BLOCKERS.md`. But the separation is enforced only by convention/documentation, not by a runtime guard rejecting the registered provider on the legacy path. This does not currently manifest as a defect (nothing in this package wires the legacy path to Binance data), but it is an unenforced boundary and is flagged as a required correction before any orchestration code is added on top of this package.

**3. Portable-path, ZIP-member, checksum, encoding, header, column, period, coverage, ordinal, and collision checks fail closed.**
SATISFIED. Independently confirmed, each with a dedicated reason code and a raise-before-return/construct site: portable-path (`RCC_SOURCE_PORTABLE_PATH_INVALID`, `profiles.py:126`, `source_identity.py:219`), ZIP-member (`RCC_SOURCE_ZIP_MEMBER_COUNT_MISMATCH`/`RCC_SOURCE_ZIP_MEMBER_NAME_MISMATCH`, `source_identity.py:213-229`), checksum (`RCC_SOURCE_PROVIDER_CHECKSUM_INVALID`/`_MISMATCH`, `:190-198`, `:388-392`), encoding (`RCC_SOURCE_ENCODING_MISMATCH`, `:241-249`), header (`RCC_SOURCE_HEADER_MODE_MISMATCH`, `:159-166`, matching the registry's `header_mode: ABSENT` / `header_like_record_action: FAIL_COMPLETE_SOURCE_SNAPSHOT`), column (`RCC_SOURCE_COLUMN_COUNT_MISMATCH`, `:261-265`), period (`RCC_SOURCE_ARCHIVE_PERIOD_INVALID`/`_CROSSES_UNIT_BOUNDARY`, `profiles.py:85-89`, `:201-204`), coverage (`RCC_SOURCE_COVERAGE_OUTSIDE_PERIOD`/`_OVERLAP`, `profiles.py:262-266`, `source_identity.py:401-406`), ordinal (`RCC_SOURCE_FILE_ORDINAL_MISMATCH`, `:318-322`), and collision (`RCC_SOURCE_DUPLICATE_NAME`/`_DUPLICATE_PERIOD_CONFLICT`, `:371-387`). All are exercised by unit tests, and the header/period/coverage/collision/ordinal checks were additionally exercised live against the real 92,160-row provider evidence (§2).

**4. Source Manifest 1.0.0 output has exactly the schema-required fields and revalidates derived identity and coverage.**
SATISFIED. `SourceManifest.as_dict()` (`manifest.py:349-379`) emits exactly the 28 keys required by `schemas/rcc002/manifests/source-manifest/1.0.0.schema.json` (`required`, 28 entries, `additionalProperties: false`); this equality is also machine-checked by `test_materializes_exact_schema_fields` (`tests/rcc002/s0/test_manifest.py:195-209`), which loads the actual schema file and asserts `set(payload) == set(schema["required"])`. `__post_init__` (`manifest.py:280-332`) recomputes `build_source_snapshot(self.source_files, ...)` and rejects any manifest whose declared identity, coverage, or file order disagrees with the recomputation.

**5. S1 source coordinates and Row ID V2 propagate without constructor, inheritance, sorting, deduplication, or stage-boundary loss.**
SATISFIED. `source_file_ordinal`/`original_record_index` are declared once, on `S1Row` (`s1/schema.py:78-79`), and inherited transitively through the dataclass chain `S1Row → S2Row → S3Row → S4Row(S3Row) → S5Row(S4Row) → S6Row(S5Row) → S7Row(S6Row)`. Propagation from S3 onward is **generic**, not hand-copied: `s4/compute.py:227-229` builds `_S3_FIELD_NAMES` from `dataclasses.fields(S3Row)` and `_copy_s3_values()` (`:755-759`) spreads every such field into `S4Row(...)`; `_verify_row_preservation()` (`:776-793`) reconciles every field, including the two new ones, row-for-row. The identical pattern (`dataclasses.fields(S4Row)`/`S5Row`/`S6Row`) is used unmodified in `s5/compute.py`, `s6/compute.py`, `s7/compute.py` — none of these three files needed to change, and are confirmed byte-identical to BASELINE. `original_record_index` is assigned by `enumerate(raw_rows)` *before* the later `sorted()` call in `normalize_rows` (`s1/normalize.py`), so it is stable under S1's own re-sort. `S1Row.__post_init__` (`s1/schema.py:117-135`) additionally revalidates that `source_row_id` decodes to exactly the row's own stored `source_file_ordinal`/`original_record_index` via `validate_source_row_id_coordinates`. S2's dedup/anomaly/segment modules (`duplicates.py`, `anomalies.py`, `segment.py`, `invariants.py`) are byte-identical to BASELINE and operate on whole `S1Row`/`S2Row` objects, never re-constructing rows field-by-field, so no drop risk was introduced. `tests/rcc002/test_s8bcp001_implementation_correction.py:32-54` directly asserts the exact field position at every one of the 7 row types.

The literal value `"rcc002.stage.s3-indicators/1.0.0"` is independently asserted, not merely re-derived, in `tests/rcc002/s3/test_schema.py:99-101` (`test_indicator_schema_ref_is_exact`). `s7/constants.py` now folds the complete, generically-derived `dataclasses.fields(S6Row)` name list into both `LABEL_SCHEMA_FINGERPRINT_SHA256` and `SEMANTIC_BUILD_CONFIGURATION_SHA256` (`:258-263`, `:289-293`), so the two new coordinate fields correctly change these deterministic identities relative to BASELINE — consistent with Reproducibility §6.5 ("jede Änderung von `semantic_build_configuration_sha256` erzeugt einen neuen `build_id`").
